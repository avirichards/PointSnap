# PointSnap airline access status

Updated September 5, 2026. This report separates working PointSnap connections, native browser evidence, cached discovery data and documented access requirements. **All-airline native live search is not complete.** Forty-one programs and booking flows are tracked; this is not a claim to have tested every airline worldwide.

## What actually works

PointSnap can search without connecting a traveler's airline account. Eight scoped sources now supply individual live flight offers in the configured local app: Alaska Atmos, JetBlue TrueBlue, Aeromexico Rewards, Frontier Miles, Ethiopian ShebaMiles, Skywards' easyJet/Jet2 partner portal, and the anonymous Delta and Smiles browser connections. Qantas adds cached international Classic Reward itineraries. Virgin Atlantic supplies a separate daily calendar.

The following are measured searches, not guarantees that every route, date or fare is available. Each source's supplied itineraries, connections and fare choices are retained; individual-source success does not establish complete airline-wide coverage.

## Why American looked close

American's new ordinary anonymous advanced-form search returns 40 LAX–AUS itineraries/72 fares; a later homepage-widget search returns 40/70. The earlier saved regression response had69 fares. These are separate observations, not a completed same-time reconciliation of both forms. The replacement parser preserves the full observed response, including the nonstop flights that were absent from the tested partner inventory. It has regression coverage and is ready to accept a real native response.

The unresolved part is obtaining that response reliably from PointSnap's own runtime. Distinct tests covered the current website's actual request contract; fresh homepage/booking initialization; request-local cookie, CSRF and correlation handling; proper redirects; ordinary browser headers; compatible HTTP/TLS clients; a separate hosted Linux network; the weekly endpoint; and the official Redemption Deals handoff. The native inventory request still returns error 309 or a verification page. Browser success and a complete parser therefore do not justify enabling AAdvantage.

A separate full-browser transport is now implemented behind an explicit experimental setting. Six actual PointSnap-triggered local attempts covered Chromium, branded Chrome in headless and visible modes, direct versus homepage entry, WebKit and Firefox. Chromium/Chrome received booking-page 403. WebKit and Firefox completed the real route/date/passenger form and submitted the search, then received Challenge Validation before flight data. Errors remain visible in PointSnap's source coverage; no fixture or native result is substituted. The additional homepage-widget implementation initially exposed a custom-radio control bug; after fixing the actual label interaction, it submits successfully and reaches the same verification page. The [sanitized evidence](evidence/american-browser-2026-09-05.json) records those eight local attempts, including that implementation failure. Four additional local tests bring the total to twelve: fresh system WKWebView at both homepage and direct entry returned HTTP 403; newly created regular Chrome and WebKit profiles respectively reached homepage Access Denied and post-submission Challenge Validation. These temporary profiles were created empty and removed afterward, without personal browser state.

The first five hosted attempts were recorded across [the initial run](https://github.com/avirichards/PointSnap/actions/runs/33996918552) and [the follow-up](https://github.com/avirichards/PointSnap/actions/runs/33997388354). Hosted Firefox submits then reaches Challenge Validation. Hosted WebKit reloads the entry without exposing the form. Downloaded Chromium initially failed to launch; switching to the installed standard Chrome fixes launch with the sandbox intact, then American returns homepage 403. The launch failure is a runtime issue, not airline-access evidence. Two additional hosted Mac attempts also fail: standard Chrome receives homepage Access Denied, while WebKit submits the actual form and reaches Challenge Validation at the flight response. This brings the recorded hosted attempts to seven. [Hosted Mac run](https://github.com/avirichards/PointSnap/actions/runs/34001080609). No complete native worker response was obtained, so this transport stays disabled in the normal app.

Offered American-operated awards can appear through Alaska and cached Qantas data. Those are different booking programs with different inventory and points prices. They are never labeled native AAdvantage results.

## Wider review and remaining options

Latest user steering permits evaluating airline-account connections as an alternative to anonymous-only access. The [access-options assessment](airline-access-options.md) compares a local browser companion, hosted authenticated sessions, connected Seats.aero Pro access and commercial suppliers. The anonymous browser-service option is now verified locally for Delta and Smiles. Companion and connected-member approaches remain unverified.

Finnair's actual Award flight tab was also opened: it asks for a Finnair Plus account before displaying the award form. Copa's newly discovered current anonymous miles booker also reaches verification: its fresh server initialization returns 403, and the normal browser displays a challenge. LATAM's actual published miles-deal link redirects to member login before flight choices. Korean Air's public availability page explicitly uses a daily cached snapshot; its real-time Mileage Booking button opens login. The detailed evidence table below distinguishes these browser findings from documentation-only reviews.

The [Seats.aero public frontend](https://github.com/avirichards/PointSnap/blob/codex/finish-pointsnap/docs/live-data.md#seatsaero-research-using-the-authorized-pro-session) was inspected using the authorized Pro session. It calls Seats.aero's servers; it does not disclose their airline connector backend. Their official [Live Search documentation](https://developers.seats.aero/reference/live-search) requires commercial access. A personal Pro account does not provide that product's live-search API to PointSnap.

The earlier investigation did not exhaust every architecture: a dedicated browser worker had not been tested end to end. That architecture now produces complete Delta and Smiles results locally. American and Southwest have separate recorded failures; Delta's success does not silently enable those programs. Denial of these particular methods is not proof that a native connector is impossible, nor does another platform's coverage disclose its private collection method. A local browser companion, authorized member sessions where needed, approved service access and other deployment runtimes remain distinct options requiring their own evidence. A Chrome companion capability check could not proceed: Chrome browser automation is unavailable in the current tool connection, and native Computer Use reports pending macOS Accessibility/Screen Recording permission. No companion, member login or session transfer has been represented as implemented or verified. No paid service or personal session has been silently substituted.
