# PointSnap airline access status

Updated September 5, 2026. This report separates working PointSnap connections, native browser evidence, cached discovery data and documented access requirements. **All-airline native live search is not complete.** Forty-one programs and booking flows are tracked; this is not a claim to have tested every airline worldwide.

## What actually works

PointSnap can search without connecting a traveler's airline account. Six scoped sources supply individual live flight offers: Alaska Atmos, JetBlue TrueBlue, Aeromexico Rewards, Frontier Miles, Ethiopian ShebaMiles, and Skywards' easyJet/Jet2 partner portal. Qantas adds cached international Classic Reward itineraries. Virgin Atlantic supplies a separate daily calendar.

The following are measured searches, not guarantees that every route, date or fare is available. Each source's supplied itineraries, connections and fare choices are retained; individual-source success does not establish complete airline-wide coverage.

## Why American looked close

American's ordinary anonymous browser returns 40 LAX–AUS itineraries and 69 fares. The replacement parser preserves the full observed response, including the nonstop flights that were absent from the tested partner inventory. It has regression coverage and is ready to accept a real native response.

The unresolved part is obtaining that response reliably from PointSnap's own runtime. Distinct tests covered the current website's actual request contract; fresh homepage/booking initialization; request-local cookie, CSRF and correlation handling; proper redirects; ordinary browser headers; compatible HTTP/TLS clients; a separate hosted Linux network; the weekly endpoint; and the official Redemption Deals handoff. The native inventory request still returns error 309 or a verification page. Browser success and a complete parser therefore do not justify enabling AAdvantage.

Offered American-operated awards can appear through Alaska and cached Qantas data. Those are different booking programs with different inventory and points prices. They are never labeled native AAdvantage results.

## United, Delta and Southwest

- **United:** the newly traced same-origin anonymous-token redirect now completes301→200. The actual award inventory request still returns 428 verification. Its normal website's miles results request member sign-in. Offered TrueBlue awards remain available; their coverage is not equivalent to MileagePlus.
- **Delta:** the current anonymous website returned 46 itineraries over20/20/6 pages. Its current GUEST GraphQL offer contract is mapped, including pagination and exact currency fields. Fresh hosted initialization succeeds, then inventory returns 444. A local compatible-client test also reaches a verification response.
- **Southwest:** the current anonymous website returned 26 itineraries and 104 fare buttons. The actual current 112.0.3 public booking configuration is available, but fresh local and hosted shopping requests return403050700.

These are failures of the tested access paths, not proof of permanent impossibility. No blocked response becomes an empty or sold-out result in PointSnap.

## Wider review and remaining options

Latest user steering permits evaluating airline-account connections as an alternative to anonymous-only access. The [access-options assessment](airline-access-options.md) compares a local browser companion, hosted authenticated sessions, connected Seats.aero Pro access and commercial suppliers. These newly reopened paths remain unverified; this does not change the enabled-source counts below.

Copa's newly discovered current anonymous miles booker also reaches verification: its fresh server initialization returns 403, and the normal browser displays a challenge. LATAM's actual published miles-deal link redirects to member login before flight choices. Korean Air's public availability page explicitly uses a daily cached snapshot; its real-time Mileage Booking button opens login. The detailed evidence table below distinguishes these browser findings from documentation-only reviews.

The [Seats.aero public frontend](https://github.com/avirichards/PointSnap/blob/codex/finish-pointsnap/docs/live-data.md#seatsaero-research-using-the-authorized-pro-session) was inspected using the authorized Pro session. It calls Seats.aero's servers; it does not disclose their airline connector backend. Their official [Live Search documentation](https://developers.seats.aero/reference/live-search) requires commercial access. A personal Pro account does not provide that product's live-search API to PointSnap.

No further reproducible anonymous native access path was identified for the remaining sources in this investigation. Repeating the same denied requests does not resolve the missing access. A newly available official public contract, an authorized data/service arrangement, changed ordinary site behavior, or an accessible production runtime would provide a concrete reason for another experiment. Account-based approaches and new paid services have not been silently substituted for the requested experience. This is the current evidence boundary, not a mathematical claim that no other method could ever exist.

## Verification and unfinished work

All 147 frontend/contract tests, TypeScript, lint, the optimized Node 22 build, GitHub CI and the Vercel preview build pass. The newly built local production server also returned complete Alaska 35/68 and Aeromexico 11/100 responses through the real search API, in 2.2 and 1.9 seconds. Real browser checks include Alaska's pagination across all 35 results and Aeromexico's 11 flights/100 fares, all three selected Business fare families, original/converted fees, and the official booking handoff. No console errors appeared in those checks.

Vercel runtime connectivity remains unverified behind the existing preview sign-in. Ethiopian's local interruption and Qantas's hosted denial are unresolved. No claim is made that the app is fully production-ready.

All prior UI/product requests remain in the [complete requirements ledger](https://github.com/avirichards/PointSnap/blob/codex/finish-pointsnap/tasks/user-requirements.md), including city-wide airport search, redesigned calendars, hidden-city comparison, advanced reference-data filters and the remaining product audit. They remain behind the airline-access priority. Changes are preserved in [draft PR4](https://github.com/avirichards/PointSnap/pull/4).
